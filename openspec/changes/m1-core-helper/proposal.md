# Proposal: M1 — Núcleo (`nopass-core` + `nopass-helper` + install data)

Change: `m1-core-helper` · Project: `nopass` · Source of truth: `docs/PRD_NoPass_Linux.md` v1.1 · Date: 2026-09-12

## Intent

The repository is empty except for the PRD. Nothing can be built, tested, or reviewed until the privileged foundation exists. M1 creates the Cargo workspace, the pure-logic crate, and the privileged helper that owns every write to `/etc/sudoers.d/`. This layer carries all of the project's security risk: the tray (M2/M3) is only a caller. Building and hardening it first means the trust boundary is specified, unit-tested, and auditable before any UI exists, and it makes the helper independently usable and verifiable from the command line.

## Scope

### In Scope

- Cargo workspace root (edition 2024, MSRV 1.85, release profile per PRD §6: `lto`, `codegen-units = 1`, `strip`).
- `crates/nopass-core` — no I/O, no UI, no system deps: rule template rendering (`#uid` syntax), header parsing (`nopass-user` / `nopass-expires`), `Expiry { Never, Reboot, At(u64) }`, duration validation, path builders, `HelperStatus` serde types.
- `crates/nopass-helper` — privileged binary, `#![forbid(unsafe_code)]`: fixed subcommands, `PKEXEC_UID`-only UID resolution, admission checks, atomic rule write, `flock`, systemd timer management, `/run/nopass/<uid>.state`, journald audit.
- Static install data: `data/com.enfoquestic.nopass.policy`, `data/nopass-cleanup.service`, `data/nopass.tmpfiles.conf`.
- Tests: full unit coverage of `nopass-core`; argv-level unit tests of every external command via a `CommandRunner` trait; root-only integration tests for file operations in a plain Debian/Fedora container.

### Out of Scope

- Tray crate `nopass`, SNI icon, menu, notifications, inotify, reconciliation (M2/M3).
- Icons, `.desktop` file, locales, `rust-i18n`, user config `~/.config/nopass/config.toml` (M3).
- Packaging `.deb` / `.rpm` / AUR and uninstall scripts (M4).
- A full-systemd container lane (optional manual smoke test, not a gate).
- Suspend/resume and reboot QA scenarios (manual, M4).

## Capabilities

### New Capabilities

- `sudoers-rule-lifecycle`: exact rule file format and header, atomic create (`O_EXCL` + `0440` + `fsync` + `visudo -cf` + `rename`), removal, NoPass-ownership identification, `flock` serialization.
- `privilege-admission`: invocation-context rules (`PKEXEC_UID` vs. uid 0), UID range admission, existing-sudoer probe, polkit action definition.
- `expiry-policy`: `Expiry` model and header encoding, `[60, 28800]` s validation, transient timer replacement, boot-time cleanup service behavior.
- `helper-cli`: fixed subcommand and flag surface, argument rejection, typed exit codes.
- `helper-observability`: `status` stdout JSON, `/run/nopass/<uid>.state` (tmpfiles-created directory), journald audit records.

### Modified Capabilities

None — `openspec/specs/` is empty.

## Approach

Two crates split along the I/O boundary. `nopass-core` holds every decision that can be made without touching the system, so it is exhaustively unit-testable. `nopass-helper` holds every syscall and every subprocess; each external program is invoked through a `CommandRunner` trait so the exact argv is asserted in unit tests without a systemd-capable container.

### Data contracts

**Rule file** `/etc/sudoers.d/90-nopass-<uid>` (tmp: `/etc/sudoers.d/.90-nopass-<uid>.tmp`, mode `0440 root:root`):

```
# Generated by NoPass — do not edit manually
# nopass-user: jorge
# nopass-expires: 1789000000
#1000 ALL=(ALL) NOPASSWD: ALL
```

`nopass-expires` accepts exactly `never`, `reboot`, or a UTC epoch integer. The username appears only in the comment and is sanitized to `[A-Za-z0-9._-]`.

**Status JSON** — one `HelperStatus` struct via `serde_json`, used verbatim for `status` stdout and for `/run/nopass/<uid>.state` (`0644`):

```json
{
  "schema": 1,
  "uid": 1000,
  "user": "jorge",
  "active": true,
  "expires": { "kind": "at", "epoch": 1789000000 },
  "rule_path": "/etc/sudoers.d/90-nopass-1000",
  "updated_at": 1789000000
}
```

`expires` is an internally tagged enum: `{"kind":"never"}`, `{"kind":"reboot"}`, `{"kind":"at","epoch":<u64>}`, or `null` when inactive.

**CLI surface** (clap derive, no permissive modes):

| Subcommand | Flags | Context |
|---|---|---|
| `enable` | none → `Never`; `--until <epoch>`; `--until-reboot` (mutually exclusive group) | `PKEXEC_UID` required |
| `disable` | none | `PKEXEC_UID` required |
| `status` | none | `PKEXEC_UID` required (no separate polkit action) |
| `expire` | `--uid <n>` and/or `--boot`; at least one required | uid 0 **and** `PKEXEC_UID` unset |

`expire --uid <n>` re-reads the rule header and deletes only when `nopass-expires` is an epoch already in the past. `expire --boot` is the `nopass-cleanup.service` entry point: it additionally treats `reboot` as expired, and without `--uid` it sweeps every `90-nopass-*` file. Keeping cleanup as a flag on `expire` avoids a fifth subcommand.

**Exit codes**:

| Code | Meaning |
|---|---|
| 0 | success |
| 1 | internal error |
| 2 | CLI parse error (clap default) |
| 10 | invocation-context violation (missing/invalid `PKEXEC_UID`; `expire` not root or with `PKEXEC_UID` set) |
| 11 | target UID rejected (missing from `getpwuid`, uid 0, outside `[UID_MIN, UID_MAX]`) |
| 12 | target user is not already a sudoer |
| 13 | duration outside `[60, 28800]` s or malformed `--until` |
| 14 | `visudo -cf` rejected the candidate file (nothing changed) |
| 15 | lock busy / concurrent operation |
| 16 | filesystem or atomic-write failure |
| 17 | timer scheduling failed (rule rolled back) |

### Security invariants (explicit)

1. `/etc/sudoers` is never written or read for modification; only `/etc/sudoers.d/90-nopass-<uid>`.
2. No file is renamed into `/etc/sudoers.d/` without a successful `/usr/sbin/visudo -cf` on the temporary file; on failure the temp file is unlinked and nothing else changes.
3. The temporary file is created with `O_EXCL|O_CREAT|O_WRONLY`, mode `0440`, owner `root:root`, and `fsync`ed before validation. Its leading `.` guarantees sudo ignores an orphan.
4. The target UID for `enable`/`disable`/`status` derives **exclusively** from `PKEXEC_UID`. No username, uid, or path argument exists on those subcommands.
5. `expire` runs only when `getuid() == 0` **and** `PKEXEC_UID` is unset; otherwise exit 10 with no system change.
6. `expire` deletes only after re-reading the header and confirming expiry, so an obsolete timer cannot revoke a newer activation.
7. Admission requires `UID_MIN <= uid <= UID_MAX` read from `/etc/login.defs` (defaults 1000/60000, floor clamped at 1000); uid 0 is always rejected; `nobody` (65534) is therefore rejected.
8. "Already a sudoer" means "may run an arbitrary command as root": the authoritative probe is `LANG=C /usr/bin/sudo -n -l -U <user> /bin/sh` exit code 0. Group membership in `sudo`/`wheel`/`admin` is a fast pre-check only. sudo's denial text is never parsed.
9. Rule content is a fixed template. The only interpolated values are the numeric uid and a username sanitized to `[A-Za-z0-9._-]`, and the username appears only inside a comment.
10. External programs are invoked by absolute path only; no `PATH` lookup, no shell, and no environment variable other than `PKEXEC_UID` is trusted.
11. `#![forbid(unsafe_code)]` in `nopass-helper`; clap rejects unknown subcommands and flags before any handler runs.
12. Every mutating operation holds a `flock` on `/run/nopass/lock` for its whole duration.
13. A single polkit action `com.enfoquestic.nopass.manage` with `allow_any=no`, `allow_inactive=no`, `allow_active=auth_admin_keep`, annotated to the fixed helper path.
14. Every `enable`, `disable`, and `expire` is logged to journald with `SYSLOG_IDENTIFIER=nopass-helper`, including uid, outcome, and expiry.

## Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| Privilege boundary defect in the helper (**high-risk area** per `config.yaml`) | Med | Invariants 1–14 become spec requirements; `forbid(unsafe_code)`; negative tests for every rejection path |
| Absolute binary paths differ across target distros | Med | Ordered list of absolute candidates resolved at startup, first existing wins; never `PATH`, never a shell; missing binary is a typed failure |
| Transient timer replacement is inconsistent across systemd versions | Med | Always `systemctl stop nopass-expire-<uid>.timer` (tolerating "not loaded") before `systemd-run`; assert the exact argv in unit tests |
| Rule written but timer scheduling fails, leaving a permanent grant | Low | Roll back the rule file and exit 17; covered by an argv-level failure-injection test |
| `sudo -l -U <user> <cmd>` semantics change upstream | Low | Documented contract in sudo(8); group pre-check retained; probe isolated behind `CommandRunner` |
| `--on-calendar` timestamp parsing | Low | Always emit UTC RFC-3339 with explicit `Z` |
| Container test lane cannot run systemd, so timer firing is unproven in CI | Med | Strategy B: argv unit tests plus root-only file-op container tests; full-systemd lane stays optional/manual, and PRD §10 suspend/reboot items move to M4 QA |
| `strict_tdd` is currently `false` because no workspace exists | High | Promote `openspec/config.yaml` to `strict_tdd: true` with `cargo test --workspace` in the first work unit, before feature code |

## Rollback Plan

M1 adds only new files to a repository with no prior source code, so `git revert` of the M1 slices (or deleting `Cargo.toml`, `crates/`, `data/`) restores the pre-change state with no migration. Nothing is installed to the system by the build itself. If an intermediate slice is reverted after a manual install during testing: `systemctl stop 'nopass-expire-*.timer'`, `rm -f /etc/sudoers.d/90-nopass-*`, `rm -rf /run/nopass/`, remove `/usr/share/polkit-1/actions/com.enfoquestic.nopass.policy`, and disable `nopass-cleanup.service`. Because every rule write passes `visudo -cf` before rename, no rollback path can leave `sudo` broken.

## Success Criteria

Mapped to `docs/PRD_NoPass_Linux.md` §10, limited to items M1 can satisfy without the tray (the helper is exercised directly via `pkexec` / CLI):

- [ ] §10.2 — after `pkexec /usr/libexec/nopass-helper enable --until <epoch>`, `sudo -kn true` returns 0 for the target user.
- [ ] §10.3 — after `disable`, `sudo -kn true` fails again and no rule file, timer, or stale state remains.
- [ ] §10.4 — a username containing `.` (e.g. `ana.perez`) behaves identically; the rule is uid-keyed and the name only appears in the comment.
- [ ] §10.5 — a non-sudoer target is rejected with exit 12 and an explicit message; no file is created even when an administrator authenticates polkit.
- [ ] §10.6 — a deliberately corrupted template produces exit 14, no rename, and a still-working `sudo`.
- [ ] §10.7 — unknown arguments (exit 2), `--until` out of `[60, 28800]` (exit 13), and `expire --uid` under `PKEXEC_UID` (exit 10) all leave the system unmodified.
- [ ] §10.10 — a `--until-reboot` activation is removed by `nopass-cleanup.service` on the next boot (verified in the manual systemd lane).
- [ ] §10.13 — every `enable`, `disable`, and `expire` appears under `journalctl -t nopass-helper`.
- [ ] Additional M1 gates: `cargo test --workspace` green with `nopass-core` fully unit-tested; `cargo build --release` under MSRV 1.85 / edition 2024; the exact argv of every `visudo`, `sudo`, `systemctl`, and `systemd-run` invocation asserted in unit tests; root-only container tests covering `O_EXCL`, mode `0440`, `fsync`, atomic rename, and `flock`.

Deferred to later milestones: §10.1, §10.8, §10.9, §10.11, §10.12, §10.14.
